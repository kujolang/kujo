## Vercel Board

**What it provides.** Board launched publicly as experimental on November 18, 2026. Vercel's managed service gives agents and people channels, threads, labels, schema-validated posts, actor/audit records, task leases, dependencies, assignment and scheduled/fanout wakeups. Hosted grants constrain actions by channel and principal. Agent profile aliases are bound to an authenticated underlying principal in hosted contexts, so a display attribution under a project or person is not proof of a Kujo actor. Hosted CLI uses Vercel login or configured deployment/principal credentials. Built-in sync covers Slack, GitHub, Linear, with optional Connect or direct provider credentials and a generic Chat SDK interface. Connect is optional for the SDK's direct integration surface. Hosted watchers can wake Vercel routes; local watcher timers require a live process. [Announcement](https://vercel.com/changelog/vercel-board-is-now-available) · [Docs](https://vercel.com/docs/board) · [Protocol and sync specification](https://github.com/vercel/board/blob/b9ae9eac224e91afd95d6d3f67d0ca034681d92a/SPEC.md)

**Open-source scope and deployment.** Inspected Board source at `b9ae9eac224e91afd95d6d3f67d0ca034681d92a`, package metadata `0.53.0`, Node ≥22.18. Apache-2.0 applies to the repository. `packages/board/src/backend-local/index.ts` exports `local()` backed by SQLite, local attachments, indexed projections and an in-process scheduler. `board()` supports local and HTTP-backed usage. This confirms embeddable/local code and the documented offline/development/CLI serve use case independently of Vercel's hosted store. It does not qualify a production multi-tenant substitute for Vercel's managed API and OIDC control plane. `packages/board/test/conformance.test.ts` distinguishes capability coverage and skips. [Source and license](https://github.com/vercel/board/tree/b9ae9eac224e91afd95d6d3f67d0ca034681d92a) · [Local backend](https://github.com/vercel/board/blob/b9ae9eac224e91afd95d6d3f67d0ca034681d92a/packages/board/src/backend-local/index.ts)

**Task and delivery mechanics worth reusing.** `server/tasks.ts#createTasks` implements claims, lease validation, dependencies, holds and lifecycle. Test sources cover competing claims, wrong/stale tokens, client IDs, batch conflicts and dependency readiness. `sync/engine.ts#createSyncEngine` normalizes and persists inbound occurrences, keeps source/target copy references, routes posts/edits/deletes/reactions and records delivery receipts; retry and duplicate/echo handling are explicit. The spec preserves identities for repeated occurrence and describes retries and dead-letter behavior. An uncertain provider-side write can still produce a duplicate, and deleting a message can leave attachments in storage. Qualify export/import, retention, tenant isolation, auth, long-duration crash recovery and provider-specific behavior before opting into a local Board backend. [Tasks source](https://github.com/vercel/board/blob/b9ae9eac224e91afd95d6d3f67d0ca034681d92a/packages/board/src/server/tasks.ts) · [Sync source](https://github.com/vercel/board/blob/b9ae9eac224e91afd95d6d3f67d0ca034681d92a/packages/board/src/sync/engine.ts) · [Task fixtures](https://github.com/vercel/board/blob/b9ae9eac224e91afd95d6d3f67d0ca034681d92a/packages/board/test/tasks.test.ts)

**Decision.** Treat Board as an optional adapter and compare its local backend to the smallest independent persistence port in a bounded conformance spike. Let it own an optional external backlog or thread store in an explicitly selected installation. Preserve task/receipt ownership in Kujo for Factory effects. The hosted API is experimental, free during that phase, subject to Vercel's beta terms, and rate-limited by login/deployment shared across profiles. The docs cap message text at 10,000 characters and list attachment limits. Reliable multi-tenant self-hosting, portability of Connect, future pricing, and API compatibility need confirmation. Avoid rebuilding claims, generic sync or scheduling that a qualified Board projection already supplies. [Board limits, pricing and beta terms](https://vercel.com/docs/board)

## Paperclip

**Upstream platform.** Public release independently checked at v2026.1106.0. Upstream source was also inspected in a local fork at its own pinned revision. Paperclip provides self-hosted MIT-licensed application code, companies, provisioned agents/API credentials, typed adapters, human membership and decision UX, issues and parent/dependency edges, assignments, issue checkout with run ownership, comments, audit surfaces, budgets and heartbeat wakeup. Agent issue comments and structured dependencies can wake eligible agents. Use explicit issue checkout/assignment plus comment routes for paper-trail coordination. Native review/approval and UI state have Paperclip-local authority. Use authenticated deployment and scope the API principal to the company, project and allowed issue. Company permissions, private issues and edition/cloud operation need validation for the exact target. [Repository and license](https://github.com/paperclipai/paperclip) · [Release](https://github.com/paperclipai/paperclip/releases/tag/v2026.1106.0) · [Issues API](https://docs.paperclip.ing/reference/api/issues/) · [Agents API](https://github.com/paperclipai/paperclip-docs/blob/main/docs/reference/api/agents.md) · [Approvals](https://docs.paperclip.ing/reference/api/approvals/)

**Native chat is more than issue comments.** In local fork `4d754ac8…`, `server/src/routes/chat-channels.ts#chatWebhookRoutes` handles provider ingress. `server/src/services/chat-channels.ts#chatChannelService`, `chat-action-work.ts` and `chat-delivery-work.ts` implement binding, durable wake/delivery work and leases. Native chat can bind a platform bot to an agent and an admitted conversation to a task, with publication policy and delivery receipts. The local fork contains Slack, Teams, Discord, GitHub and other provider paths and scoped historical live qualifications. The upstream October release describes experimental connectors, and Slack documentation flags incomplete functionality and a separate agent-tool connector. Edits/deletes, provider retry and transcript access vary by adapter; the issue API should use reconciliation, bounded retries and explicit operation IDs, with no assumed global quota, generalized event replay, chat parity or webhook SLA. Qualification must check exact server/plugin versions and provider scope. [October release](https://github.com/paperclipai/paperclip/releases/tag/v2026.1005.0) · [Slack connector](https://github.com/paperclipai/paperclip-docs/blob/main/docs/connectors/slack.md) · [Bring your own agent](https://github.com/paperclipai/paperclip-docs/blob/main/docs/how-to/bring-your-own-agent.md)

**Kujo plugin.** `kujolang/paperclip` v0.3.0 contains hosted plugin projections, workspace authorization, bounded Kujo component execution, Dispatch history/control and decision observation, RunLedger and Watchdog receipts, and other tooling. It contributes neither upstream company/agent records, native Slack/Teams endpoints nor the issue checkout scheduler. Candidates are a plugin-hosted intent/receipt adapter and a scoped upstream runner bridge. Paperclip assignment can request a Factory mission. Final execution and native approvals remain provable inside Kujo. If Paperclip already mirrors Slack for a thread, register only one ingress/sync owner. [Kujo plugin source](https://github.com/kujolang/paperclip/tree/5109b966005ff389b61aafe287cfc0cf1288ac39)

## Reusable transport and protocol boundaries

- Vercel's separate MIT Chat SDK provides transport adapters including Slack, Teams, Discord and GitHub. Use behind an interface after checking auth, event identity, ack timing, 429, crash and reply support per adapter. Its cache/state abstractions do not establish Kujo admission or delivery durability. Compare this against a small direct Slack adapter and Leash's bounded ChatOps before choosing dependencies. [Chat SDK](https://github.com/vercel/chat) · [Official guide](https://vercel.com/kb/guide/the-complete-guide-to-chat-sdk)
- A2A Agent Cards, messages, tasks, contexts and updates are suitable for federated external agents later. Agent discovery metadata is not a trusted workspace membership grant. Map an A2A task only to an external request/operation, never to a duplicate Dispatch state machine. ACP addresses harness/client session interaction. MCP/Abilities describe scoped tools and discovery. [A2A spec](https://a2a-protocol.org/latest/specification/) · [ACP](https://agentclientprotocol.com/protocol/v1/overview)
- CloudEvents supplies source/id/type/version conventions for transferable metadata. It does not standardize chat permissions, durable acknowledgement or delivery. Start with an aligned envelope and publish a CloudEvents mapping before claiming wire compatibility. [CloudEvents core](https://github.com/cloudevents/spec/blob/main/cloudevents/spec.md)
