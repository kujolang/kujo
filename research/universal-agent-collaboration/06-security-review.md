# 06. Security and accountability

## Trust and effects

External transports are untrusted content and separately authenticated installations. Connector host can normalize and queue events. It cannot hold a provider model key, Factory worker shell, Ops resume capability, release credential or access to Workcell control. The collaboration edge owns admission records and output publication policy. The Factory local operator and controller own effect admission. Native recovery and independent release gates remain separate. Authenticate both sides of edge → controller with local OS capability and exact prepared submission digest first. Hosted identity and transport certificate boundary is future work.

| Threat | Existing control to reuse | Required protection before external invocation |
|---|---|---|
| Slack spoof, Teams forgery, stale replay | Leash `verify_slack_signature`, Discord verifier, bounded payloads; Microsoft connector authentication contract | Slack raw bytes, signing key and timestamp freshness before parsing. Socket Mode authenticates the outbound socket plus installation binding and envelope ack. Teams requires maintained JWT verifier with trusted keys, issuer, audience, expiry, service URL/channel checks where applicable and allowed tenant/app. Subscribe only to required events. [Slack verification](https://docs.slack.dev/authentication/verifying-requests-from-slack/) · [Teams connector authentication](https://learn.microsoft.com/en-us/azure/bot-service/rest-api/bot-framework-rest-connector-authentication) |
| Identity impersonation and cross-workspace access | Local Factory UID grant, Ability Gateway tenant/auth patterns, Paperclip workspace guard | Bind immutable platform installation and subject to enrolled Kujo IDs. Map independently of display name. Validate project/channel/private visibility per action. Require proof and audit for link/relink, deny stale or revoked versions, isolate connector secrets and stores by workspace. |
| Mentions and agent identity misuse | Factory role/task bindings, SDK target allowlists and depth guards | Ordinary message/mention creates context only. Any wake or delegation is a typed request with distinct permission, pinned role, bounded target set and operator review. Use distinct actor kinds; no ability to provide arbitrary actor IDs in adapter input. |
| Prompt injection and unauthorized tools | Factory's text-only proposal interface, bounded role schemas, fixed worker argv, Dispatch policy plus Workcell effective controls | Keep data separate from instructions and capabilities. Permit only sealed mission kind and fixed worker effects. Quarantine unsupported content, external URLs and attachments. Block adapter/tool/credential grants issued by models, instructions in messages or bot self-posts. |
| Secret leaks and retention | Factory secret-egress, artifact scanner, evidence gates and Casefile redaction | Generate allowlisted summaries; never mirror prompts, logs, env, credentials, arbitrary artifact paths or private review text. Redact before store/fanout when possible, scope recipients again at delivery. Set explicit content TTL and cross-provider deletion policy, retain minimal audit metadata separately, and disclose remote retention/legal holds. Native evidence requires its existing authorization. |
| Approval forgery, stale/duplicate decisions | Dispatch revision-bound intervention checks and ownership of native decisions. Factory MCP approval-request returns false approval/deployment flags. Release policy, independent checks, source hashes and accounting remain mandatory | Pilot approval click opens trusted operator context only. For future conditional approval mapping, authenticate linked human with dedicated grant, short-lived one-use nonce and UI CSRF protection, verify native decision ID, revision, attempt, proposed effect, policy and artifact hash, and recheck current authority under native lock. Never set auto-approve from channel data. |
| Duplicate execution, lost ack or reordered delivery | Dispatch run lock, append-only decision evidence and durable outbound hooks. Factory writes `submitted.json` before child launch, refuses claiming arbitrary PIDs | Distinguish transport occurrence, intent key and delivery write key. Durable ack after intake; conditional state transitions under workspace transaction; replay links recorded authority. After crash with uncertain spawn or publish require reconciliation, never infer success, rerun a model or auto-send an ambiguous write. No cross-provider total ordering claim. |
| Wake loops and unauthorized spending | SDK handoff loop state, Factory admission limits, provider budgets and sealed scope, Dispatch retry/fallback bounds | Ignore adapter/bot mirror events by default. Correlate root/parent, enforce allowlisted peer target, one hop and one request at pilot. Apply principal/workspace quota before admission and recheck budget after queue/restart. No automatic retry of denied/stale intent. |
| Cross-factory or host escalation | Workcell defines bounded backend-specific capabilities and receipts, Factory workers select fixed tool/pack and independent release workflow | Use opaque local bindings and least privilege. Disallow pack/team/source/environment/channel override, and arbitrary shell/URLs/paths. Initially limit to one deployment. Require per-target capabilities and consent before cross-factory intents. |
| Interrupted workflow/revoked connector | Factory trusted recovery checks run/native bindings, completion checkpoints, liveness and original deadline; Dispatch state is authoritative | Reconcile from prepared, submitted and terminal records. Quarantine unknown launch and stale receipts. Human controls resume through native interfaces. Revocation stops delivery/intake and affects queued requests after recheck. |
| Tenant/user isolation in hosted deployments | Plugin workspace authorization, Gateway consent/audit patterns, backend policy and Factory checks | Qualify authenticated sessions, tenant isolation and federation separately. Verify audit boundaries and operational capabilities of selected store. A single POSIX user grant is insufficient for general multi-user hosting. |

The key distinction for review is between a request to perform work, the controller-authorized start, the native workflow state, and each publication receipt. An external closure or approval is durable evidence of a platform action only. It cannot approve or settle an internal mission. A transport accepting a delivery never proves a second service consumed or authorized it.

## Gate before any live pilot

Use synthetic fixtures to verify request authentication, stale/revoked identities, role isolation, quotas, replay, race/crash recovery, retention and redaction. Run a no-model fixture through the same admission boundary and preserve hashes and outcomes. Inspect local operator consent, controller fixed argv and denied deploy state. Only after separate human authorization can a sandbox Slack workspace, limited initial recipients and bounded production-style mission prove API and identity behavior. Teams, Board and Paperclip each need independent live qualification for bind/reply, revoke, limits and uncertain delivery. See [pilot tests](10-proof-of-concept-spec.md).
