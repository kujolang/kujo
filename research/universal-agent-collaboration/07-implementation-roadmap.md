# 07. Implementation roadmap

Every phase requires human review of the research before implementation. Complexity is relative to the existing controller and dependency surface. Fixture and live qualification have separate acceptance gates.

| Phase | Repositories and reuse | New boundary, compatibility and dependencies | Tests, security and acceptance | Estimate / confidence |
|---|---|---|---|---|
| 0. Choose the boundary | Proposed shared collaboration repo, Software Factory, WebOps Factory, Kujo Agents and Dispatch. Reuse local control, pinned roles, handoffs, native state and observer | Review workspace grants and exact opt-in command types, publication policy, event v1 and native ownership. Confirm whether a per-mission staged assistance response plus new bounded invocation is sufficient for pilot. No native format change. | Approve threat model, fixture, replay semantics and out-of-scope list. Name owner of caller-to-submission reconciliation. | Small / high |
| 1. Local/custom proof | Shared collaboration repo plus Software Factory and WebOps Factory. Reuse Software Factory local control and WebOps fixed review/evidence flows | Publish the opt-in local package, host interface, scoped principals, event schema and bounded store. Software Factory implements the first host binding. Add a WebOps read-only evidence/review binding and an Agents SDK no-effect standalone fixture as portability gates. Keep native arguments and outputs compatible. Store accepted intent keyed to its prepared ID before submission. Add typed, advisory handoff output or controller-derived assistance signal as an opt-in profile. | Offline two-agent role fixture, reviewer request and result, queued human start, restart and duplicate tests, unchanged native release gates and egress deny cases. Open a mission from the custom interface and observe linked evidence. Verify the shared package can run without Software Factory installed. WebOps evidence reaches the same UI through its own host binding. | Medium / high |
| 2. Slack vertical and independent path | Shared collaboration repo, Kujo Agents and agents.kujolang.ai. Reuse Chat SDK Slack transport or a direct connector guided by Leash, and the Phase 1 custom interface | One bot identity, explicit scoped binds, thread updates, source occurrence dedupe, provider mapping, and allowed statuses. Connector can run outside each host controller. Publish a versioned, credential-free compatibility index and project it into agent and team pages. Slash/interaction/mentions only stage typed intents. Separate install approval. | Use signed fixture plus independent custom path first. After approval, deliver in one sandbox workspace, prove same agent IDs and payload shape in both interfaces and same thread correlation. Redelivery, revoke, 429, edit/delete, mirror loops and external approval denial. Require a second independent network before declaring provider portability. Use Matrix with a dedicated bot and bounded room. | Medium / high for custom, medium for live Slack/Matrix |
| 3. Reuse qualification | Software Factory and existing Kujo Paperclip plugin. Compare Board local/hosted, Paperclip issue/wakeup and Chat SDK Teams | Conformance spike for Board storage and sync ports, compare export/retention, isolation and uncertain sends. Paperclip host API maps issue → intent → native receipt and keeps Paperclip scheduling distinct. Teams adapter uses maintained SDK/JWT path and conversation references. Pin tested versions. | Board crash/reopen, external principal scopes, replay, opt-out and mirror dedupe. Paperclip checkout/run, revoked workspace and closed issue must not change native run. Teams endpoint verifies tenant and installation and handles proactive failures. No new collaboration authority. | Medium to large / medium |
| 4. Cross-factory and hosted | VideoOps, Publishing House and Product Launch, plus standalone Agents SDK hosts. Reuse native review, signed decisions, child evidence and shared profile/Ability contracts | Adopt the shared package with workload-specific host bindings and enable request grants per factory. Review hosted tenant identity, object ACLs, service auth, concurrent event fanout, retention and disaster recovery. Add A2A or external adapter if justified. | Local cross-factory handoff with destination-owned gate, revocation, blocked source impersonation, drain/replay and export/import tests. Hosted isolation/restore/effect-only qualification before enabling general work. | Large / medium-low until adoption |

Prioritize Phases 0–2. See the [factory and registry integration contract](11-registry-and-factory-integration.md). To prove portability, run both surfaces against the same workspace bindings and same canonical IDs, including a cross-interface reply. For external-network portability, add Matrix as the next test because it can be separately hosted and does not share Slack APIs or identity. Do not route the two initial adapters through one provider's mirrored feeds. Keep Board and Paperclip task semantics optional. Avoid a common execution scheduler, general chat UI, separate approval ledger and new broker in the initial milestones.
