# 08. Executive decision

**Approve a small, platform-neutral collaboration boundary in Software Factory for a two-interface pilot. Keep execution, verification and approval in the existing Kujo components.**

Kujo already has versioned role profiles, dependency-aware assignments, scoped handoffs, local control grants, bounded worker execution, run and approval journals, retry/recovery, independent release gates and a read-only Factory Floor. Leash has Slack/Discord ChatOps. Agents SDK has typed handoffs and model sessions. Product Launch already composes multiple factories through pinned child evidence. None of those paths establishes a shared authenticated workspace conversation and durable cross-platform intake for Software Factory.

Reuse Kujo Agents for profile definitions, Software Factory for admission and local release, Dispatch for execution state and interventions, Workcell for effective controls, and the existing evidence systems. Build a narrow workspace identity and binding layer, typed conversations and requests, durable occurrence and delivery tracking, and redacted projections. Preserve external task ownership only where the task belongs to the external system. Avoid a second scheduler or approval engine, a general messaging product, an early broker and a new repository.

Start with the local/custom interface and Slack. One registered, bounded Factory team should accept a human-staged mission, surface an agent-originated help/review request, and retain a correlated reply and native receipt. Use the same workflow and identity through both interfaces. Then use Matrix for independent external-network proof. Board is a strong optional adapter or storage candidate with an actual open local backend; its managed API is experimental. Paperclip has an established issue/agent API and native chat in its own platform. Kujo's plugin is the best place to add that boundary after the pilot. Teams follows with separate authentication and tenant qualification.

The recommended long-term architecture keeps one Kujo contract at the collaboration boundary and interchangeable local or external transports and thread stores. An external mention or approval can request a transition. The controller and native decision contract determine whether it can happen. Live external account behavior was outside verification.
