# 08. Executive decision

**Give collaboration its own shared package and repository. Use Software Factory for the first execution pilot, and require WebOps and a standalone agent to prove that the package works independently.**

Kujo already has versioned role profiles, dependency-aware assignments, scoped handoffs, local control grants, bounded worker execution, run and approval journals, retry/recovery, independent release gates and a read-only Factory Floor. Leash has Slack/Discord ChatOps. Agents SDK has typed handoffs and model sessions. Product Launch already composes multiple factories through pinned child evidence. None of those paths establishes a shared authenticated workspace conversation and durable cross-platform intake for Software Factory.

Reuse Kujo Agents for profile definitions, each factory for its own admission and local release, Dispatch for execution state and interventions, Workcell for effective controls, and the existing evidence systems. Build a narrow workspace identity and binding layer, typed conversations and requests, durable occurrence and delivery tracking, and redacted projections. Preserve external task ownership only where the task belongs to the external system. Avoid a second scheduler or approval engine, a general messaging product and an early broker. Publish connector compatibility in the agent registry and show setup options on agents.kujolang.ai. Use the same connector runtime for individual agents and complete factory teams.

Start with the local/custom interface and Slack. One registered, bounded Factory team should accept a human-staged mission, surface an agent-originated help/review request, and retain a correlated reply and native receipt. Use the same workflow and identity through both interfaces. Then use Matrix for independent external-network proof. Board is a strong optional adapter or storage candidate with an actual open local backend; its managed API is experimental. Paperclip has an established issue/agent API and native chat in its own platform. Kujo's plugin is the best place to add that boundary after the pilot. Teams follows with separate authentication and tenant qualification.

The recommended long-term architecture gives VideoOps, WebOps, Publishing House, Product Launch and standalone agents one collaboration contract, with independently governed host adapters and interchangeable transports and thread stores. An external mention or approval can request a transition. The controller and native decision contract determine whether it can happen. Live external account behavior was outside verification.
