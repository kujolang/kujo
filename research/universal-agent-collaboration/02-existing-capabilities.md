## How agents interact today

| Question | Implementation and boundary |
|---|---|
| Create and register | Kujo Agents publishes versioned profile definitions in `agent-registry.json` and `chain-of-command/*/manifest.json`. Software Factory binds a profile with `roleContract` in `factory/role-runtime.mjs` and resolves local catalog files and trusted skills. Agents SDK creates runtime agent objects and accepts a caller-owned handoff registry. Agent City imports and binds profiles with `apps/runner/agent-catalog.ts#importCatalog`. Each identity has a different scope. |
| Assign and discover | Factory `applicationTeam` and `repositoryTeam` compile selected roles, dependency order and advisory scopes into work orders. `factory/cli.mjs` emits `agent.assigned`. A worker selects the role mapped to its exact task. The SDK's `resolve_handoff_registry` and `resolve_handoff_target_agent` resolve agents configured by the caller. No verified workspace-wide principal lookup, presence or general address resolution was found. |
| Delegate and hand off | Factory `worker.mjs#handoff` emits a `kujo.handoff/v1` artifact containing assignment, current and next role, scope, evidence, permission mode and stop condition. The worker records acceptance while starting the scoped task. Its verification branch can route bounded correction back to developer roles. SDK `resolve_explicit_handoff_request` handles typed handoff requests, allowlisted targets and loop state, with child execution inside the runner. Dispatch `execute_handoff_step` serializes workflow handoff data. These are distinct contracts. |
| Coordinate execution | Factory's `dispatch.kujo` converts the frozen DAG to Dispatch tool steps and launches fixed worker argv. Dispatch `run_workflow_unlocked` handles dependency readiness, bounded execution, results, attempt accounting, fallback, approval boundaries and terminal state. A Factory task with a role label uses a Factory worker, not an Agents SDK chat identity. |
| Retain context | Software Factory retains work orders, proposals, receipts, handoffs, reports, Dispatch state and journals. Workers read bounded upstream artifacts into later model prompts. The SDK `sessions/store.kujo` exposes create/get/update/list/delete and save/get run state, including an in-memory implementation and an injected store interface. These are model-turn context records. Agent City `Journal` persists unique event IDs and content hashes in SQLite and rebuilds world views via replay. Project context and interaction evidence are local surfaces. A durable peer transcript with participant ACL and external thread mappings was not verified in Agent City. |
| Initiate without a new human prompt | Factory automatically emits `agent.blocked` and can generate controller-routed corrections during an existing run. Its provider prompt explicitly has no tools or additional agents. No general addressable message send or arbitrary peer wake was found on this path. SDK bounded child handoff and Paperclip wakeups are meaningful narrower analogues. |
| Trigger work from an external message | Factory can consume a GitHub issue via a bounded read in `executeMissionWorkflow` and feed a fixed configured route. The issue content is frozen as untrusted data. The existing GET is initiated by authorized local code. `control-mcp.mjs#createControlSession` adds locally granted prepare, submit, cancel, status, bounded evidence, and request-approval receipt tools via stdio. Neither constitutes an authenticated external message ingress. Upstream Paperclip has its own native chat-to-task path. |
| Recover and retry | Factory `operations.mjs` binds exact provenance, workflow, pack, native revision and checkpoints, with explicit local operator recovery and original deadline. `control-mcp.mjs` persists submit before spawn and refuses redispatch of a recorded uncertain submission. Dispatch `intervention.kujo` checks control boundary, attempt and effect safety, with revision-bound and legacy paths. Delivery retries in Dispatch `hooks.kujo` belong to webhook effects. |
| Across factories | Product Launch `scripts/child.py` plus `src/core.py#seal/verify/approve` show parent-child artifact orchestration across factories. Shared profiles and workflow packs support consistent roles. An addressable peer from another running factory and a common external conversation have no verified path in this cut. |
| Between runs | Catalog profile IDs and retained evidence survive runs. Fresh invocations and grants are bound to the execution context. A durable workspace-agent principal, credential linkage and inbox are separate requirements. A user-facing handle is display metadata. |

## Existing transports and assurance

- Dispatch `hooks.kujo#emit_hook_event` has callbacks, serialized JSONL sink and optional signed HTTP deliveries. The durable webhook path registers delivery, bounds attempts, records results, supports replay, and enforces destination policy. Its durable file protocol is an outbound execution hook, with no external installation or shared conversation subscription. `control_journal.kujo` separately records native control events. Workflow state lives in Dispatch, including its selectable filesystem/SQLite backing.
- Leash `daemon/src/main.rs` exposes Slack/Discord interaction and message routes; `daemon/src/chatops.rs` verifies signatures, normalizes actions, redacts, renders and validates decisions. `API.md` describes delivery retry with unchanged accepted decision, and ingress idempotency. Harness adapters include Codex and Claude Code. Treat these as reusable security/interaction patterns; no dependency on the untagged daemon is required for the pilot.
- Relay `src/cli.kujo` and `schemas/{chat,event-bundle,run}.schema.json` expose chat and run event artifacts, verification, retention and signed exports; `src/agent_bridge.kujo` invokes the SDK locally. These are execution surfaces and are scoped to Relay's own access/policy model.
- Kujo Paperclip `src/worker.ts`, Dispatch `control.ts` and `decision-observation.ts`, and `workspace-guard.ts` import or invoke scoped components and retain host/native receipts. Upstream Paperclip agent, issue, approval, chat transport and wakeup are independent, detailed in [04](04-platform-research.md).
- Factory Floor routes in `factory/cli.mjs` and `mission-observer.mjs` are GET-only, bounded and scoped. `operator-model.mjs` derives recorded states and correlates control evidence. MCP read-only is the default. The separate elevated stdio surface never grants deployment, and `request-approval` persists a request without satisfying a native decision. Historical Floor qualification exercised a rootless browser against synthetic observer data (zero model calls), not live chat.
- Existing GitHub read qualification is retained separately as `docs/GITHUB-ISSUE-QUALIFICATION.json` and `docs/GITHUB-READ-QUALIFICATION.md`. Local negative routing test mocks fetch and checks the frozen issue and fail-closed delegation; even a verified live GET establishes no external event receiver.
