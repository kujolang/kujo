# ZIP 9 migration for Rust embedders

This unreleased change upgrades Kujo's ZIP dependency from 7.2.0 to 9.0.5 to
resolve RUSTSEC-2026-0367, RUSTSEC-2026-0368 and RUSTSEC-2026-0369. All previously
enabled default compression features remain enabled. ZIP 9's Rust 1.88 minimum
fits Kujo's declared Rust 1.89 minimum.

## Kujo-language compatibility

No `.kujo` migration is required. Archive builtin names, arguments, capability
checks, successful return shapes and CLI exit codes are unchanged. `unzip`
continues to reject traversal and archive symlinks, check existing ancestors,
stage privately, bound decoded output, preserve existing destination permissions,
and publish only validated payloads. Archive privileged permission bits are not
applied to extracted files. In-root ancestor aliases remain supported.

Both `unzip` and `zip_single_file_read` retain ZIP 7's filename interpretation:
UTF-8 when the encoding flag is set (including validated Info-ZIP UnicodePath
fields), otherwise IBM CP437. A private compatibility decoder avoids ZIP 9's
UTF-8-first heuristic changing names in existing CP437 archives.

Malformed archives may be rejected earlier by ZIP 9's stricter header/decoder
validation. Oversized decoded entries still produce Kujo's established
`decoded size does not match declared size` diagnostic, though the byte-count
detail reflects early rejection. CRC errors remain distinct. Do not depend on
byte-for-byte upstream diagnostic details for malformed archives.

## Authorized Rust API change

With `runtime-archive` enabled, the public field remains syntactically:

```rust
Value::ZipArchive {
    writer: Arc<Mutex<Option<zip::ZipWriter<std::fs::File>>>>,
    path: String,
}
```

Its concrete writer type now comes from **zip 9**, not zip 7. Those are distinct
Rust types. Embedders constructing or destructuring this variant must migrate
their direct dependency alongside the corresponding Kujo checkout/release:

```toml
[dependencies]
zip = "9.0.5"
```

Recreate writers with the new crate; there is no supported cast or in-memory
conversion from a zip 7 writer. Finish existing archives before upgrading, then
reopen the ZIP bytes/files normally. The standard archive format is unchanged.
Consumers that do not handle this Rust variant directly need no source change.
This is an explicitly authorized Rust source-compatibility break, not a claim
that Kujo 1.8.1's already-published artifacts have changed.

Other upstream API adjustments relevant to embedders:

- `ZipFile::name()` returns `ZipResult<Cow<'_, str>>`; handle failure and use
  `.into_owned()` when retaining the name beyond the borrow.
- `ZipFile::data_start()` returns `Option<u64>`; handle an unavailable offset
  explicitly. Kujo's native updater rejects it and retains checked size and
  central-directory envelope validation.

The external integration test in `tests/zip_migration_compatibility.rs` constructs
and finishes the public writer using zip 9, then verifies the binary payload.
Language regressions exercise VM and interpreter filename handling, CRC failure,
privileged modes, ancestor confinement and decoded-size failure preservation.
Six committed archives generated by ZIP 7 exercise Stored, Deflate, Bzip2, Zstd,
XZ and PPMd decoding through both language runtimes and both archive readers.
The existing Deflate64 and LZMA features remain enabled; the ZIP 7 writer cannot
produce those fixtures, so these tests do not claim coverage of those codecs.
