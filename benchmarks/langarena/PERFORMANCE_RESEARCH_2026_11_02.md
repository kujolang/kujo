# Kujo performance investigation and bounded engineering plan

Date: 2026-11-02. Research only; no runtime or benchmark fixes, commits, pushes, publication, or maintainer contact. The existing checkpoint stays closed. Recommendations require a separate implementation authorization.

## Conclusion

The gap is plausible because Kujo often executes a much more expensive operation for each source-level operation. A compiled Kujo function can still turn an array read into a checked runtime-helper call, carry collection values through root tables, dispatch a recursive call through the VM, and update a nested field through dictionary lookup and ownership/depth validation. Rust and the pinned Goose port mostly operate on statically typed arrays, records, slices and direct calls. Removing bytecode dispatch helps, but does not remove those costs.

The strongest next targets are **generic collection operations in native code, VM-mediated calls and ownership transfers, and JIT compilation economics**. VM dispatch/value layout is a broad additional opportunity. Port differences must be tracked separately: QuickSort does different partition/recursion work, MergeSort uses element-wise copying, CacheSimulation uses string-key links, and typed JSON mapping does extra conversion work. These differences invalidate a claim that the reported ratios measure compiler quality alone; they do not make the observed gaps disappear.

Do not promise Rust or Goose parity. Dynamic values, checked arithmetic, snapshots, dynamic rebinding, catchable failures and capability boundaries have real costs. Guarded specialization can remove redundant work while preserving them; replacing Kujo's contract with shared mutable references cannot.

### Concrete port/work differences

**QuickSort.** [benchmarks/langarena/src/30_sort.kujo:9](/Users/robertdevore/2026/Kujolang/kujo-repos/kujo/benchmarks/langarena/src/30_sort.kujo:9) chooses `floor((low+high)/2)` and unconditionally makes both recursive calls, including empty/base cases. [benchmarks/sort_quick.rs:9](https://github.com/kostya/LangArena/blob/3c9f84ddaeec834c0631747cb789e8cfd602f993/rust/src/benchmarks/sort_quick.rs#L9) and [sort.goose:18](https://github.com/kostya/LangArena/blob/3c9f84ddaeec834c0631747cb789e8cfd602f993/goose/src/sort.goose#L18) choose slice `len/2` and guard recursive calls. **MergeSort.** [benchmarks/langarena/src/30_sort.kujo:24](/Users/robertdevore/2026/Kujolang/kujo-repos/kujo/benchmarks/langarena/src/30_sort.kujo:24) returns a two-array state through recursion and copies the range using indexed reads/writes. All retain the same split/merge structure, but bulk copying and element layout differ. Kujo must preserve the original input array as a snapshot. **NeuralNet.** [benchmarks/langarena/src/49_neural.kujo:1](/Users/robertdevore/2026/Kujolang/kujo-repos/kujo/benchmarks/langarena/src/49_neural.kujo:1) has 13 neurons, 30 synapses, four XOR training pairs repeated 1,000 times per iteration, rate/momentum 0.3, sigmoid activation and the same training order as [benchmarks/neural_net.rs:125](https://github.com/kostya/LangArena/blob/3c9f84ddaeec834c0631747cb789e8cfd602f993/rust/src/benchmarks/neural_net.rs#L125) and [neural_net.goose:151](https://github.com/kostya/LangArena/blob/3c9f84ddaeec834c0631747cb789e8cfd602f993/goose/src/neural_net.goose#L151). ### 1. Guarded native collection and field operations

**Mechanism/evidence.** `indexed_read` validates a native root, checks Value/index kinds and bounds, uses immediate scalar encoding where possible, otherwise clones/roots the result; generic variants call VM indexing ([src/jit.rs:1403](/Users/robertdevore/2026/Kujolang/kujo-repos/kujo/src/jit.rs:1403)). The compiler's “in place” name does not imply a raw array load. Nested stores use `jit_update_binding_path`/`jit_mutate_binding_path` ([src/jit.rs:1871](/Users/robertdevore/2026/Kujolang/kujo-repos/kujo/src/jit.rs:1871)), and cached depth metadata still performs release/remember work ([src/interpreter/assignment.rs:350](/Users/robertdevore/2026/Kujolang/kujo-repos/kujo/src/interpreter/assignment.rs:350), [src/interpreter/assignment.rs:458](/Users/robertdevore/2026/Kujolang/kujo-repos/kujo/src/interpreter/assignment.rs:458)). Accepted post-warmup profiles at 55e2f683 see these paths in QuickSort/MergeSort/NeuralNet; source reinspection shows they remain at 782c712d. The precise profile is historical, not a newly collected accepted-CLI CPU sample.

**Direction.** Start with a guarded read-only array view and fixed field shape inside one callback-free native region. Hoist root/type/shape validation, retain bounds/error behavior, and invalidate on any callback or storage/ownership change. Alternative: fuse adjacent index/path helpers without exposing a long-lived pointer. A larger typed-array/shape tier follows only after this local proof. Current scalar reads already avoid per-read owned roots; do not “fix” that again.

**Risks/dependencies.** Negative/floating index behavior, stale/recycled handles, mixed arrays, callback mutation, missing keys, struct field errors, depth limits and write atomicity must survive. Depends on an explicit view validity boundary and #2's callback contracts, not on dropping COW.

**Measurement/falsification.** Before/after count helper calls and root lookups for 8/256/8,192-element arrays, single/repeated reads, width/depth sweeps and mixed types. Pair unchanged QuickSort/MergeSort/NeuralNet and Cache test cases. Require fewer helper crossings on disassembly/trace and unchanged outputs in all three engines. If self CPU and allocations in these helpers are small, or eliminating repeated lookup fails to reduce matched whole-workload time, lower this priority. No predicted multiplier.

### 2. Calls, frames, root ownership and recursive transfer

**Mechanism/evidence.** [src/jit.rs:4662](/Users/robertdevore/2026/Kujolang/kujo-repos/kujo/src/jit.rs:4662) marshals through a Value stack and VM dispatcher; it performs two pre-callback and one post-callback environment reads for `DEBUG_JIT_CALL`. Existing profiles include `getenv`/environment locks. Argument vectors and root stores already have bounded reuse ([src/native_owned.rs:85](/Users/robertdevore/2026/Kujolang/kujo-repos/kujo/src/native_owned.rs:85)); this is not “one fresh vector per call” anymore. Owned operands use recyclable handle slots and lookup tables ([src/native_owned.rs:71](/Users/robertdevore/2026/Kujolang/kujo-repos/kujo/src/native_owned.rs:71), [src/native_owned.rs:420](/Users/robertdevore/2026/Kujolang/kujo-repos/kujo/src/native_owned.rs:420)). Integers/floats/bools/null are immediate payload/kind pairs, not individually heap boxed. Quick/Merge native entry counts make residual call cost plausible; NeuralNet repeatedly crosses small helper boundaries.

**Direction.** Tactical: remove duplicate pre-call diagnostic lookup while retaining the mandatory post-callback re-read, if isolated measurements justify it. Then add a guarded known-callee path for bytecode functions with positional owned-argument transfer, avoiding roundtrips through the generic Value stack. Alternative: inline a bounded leaf helper such as `idiv` with equivalent numeric checks; larger work is interprocedural specialization/escape analysis. Do not assume all dynamic call targets are immutable.

**Risks/dependencies.** Dynamic rebinding, caller/callee depth budget, snapshot liveness, exception propagation, capability/output context, callbacks changing environment flags and cancellation. Depends on #1 view invalidation and root lifetime proof; release/promote only the correct activation's roots.

**Measurement/falsification.** Count marshaled Values, roots inserted/released, buffer allocations and environment reads across scalar/owned arities 0–4 and recursion depths 1/8/64. Measure unchanged sorts/neural and captured/try controls. Gate VM/interpreter/JIT parity, callback enable/disable/error cases, stale handles, root high-water bounds and exact depth errors. Demonstrate the specialized call instruction executes and fallback preserves side-effect counts. If bridge self time is minor, or fewer bridge operations produce no repeatable end-to-end benefit, defer architectural inlining. Root hash substitutions previously regressed scalar reads; see historical rejection below.

### 3. Compilation economics and worker reuse

**Mechanism/evidence.** Hot-function policy uses call count/backedge presence, not estimated compilation cost versus remaining work. At depth 4 each tree construction/traversal visits 31 nodes; one warmup plus three measured iterations reaches 124 calls, crossing 100 near the end. New phase markers put the large pause in measured iteration three. Original JIT fails compilation of `tree_new`/`tree_sum` and arena counterparts; accepted JIT compiles them. All pass checksums. This is increased native coverage with poor short-run economics, not evidence that the old compiler generated faster tree code.

Keep a fixed accepted baseline and one candidate per experiment, including negative results. Stop an experiment after its predeclared semantic/cost gate fails; do not accumulate speculative changes into an un-attributable patch.

**Entry gates:** accepted source/binary hashes verified; worktree excludes the lifetime candidate; host disk/RAM adequate for one bounded build; unchanged tests/configuration frozen; new phase/cost counters have no measurable effect in uninstrumented comparisons; per-change correctness oracle, target path and failure criteria written before editing. **Delivery limit:** one tactical implementation and at most one revision of its hypothesis per experiment. Review accept/reject before taking the next architecture item. **Exit gates:** VM/interpreter/JIT differential tests pass; optimized native/VM path actually executes; boundary errors, snapshots, capability/cancellation behavior and root bounds hold; all 50 unchanged test-size workloads pass in each claimed mode; repeatable target improvement survives independent sessions; no unexplained controlled-host regression greater than 5%, memory growth, hidden failure or timeout. Five percent is an investigation threshold, not permission to accept every smaller slowdown. Archive compiler/input/binary identity and rejected samples. Complete repository-required formatting/build/integration gates before accepting source changes. Production/clean-host results remain separate acceptance stages.

**Amdahl discipline:** use `S = 1 / ((1-f) + f/s)` only once self-time coverage `f` is measured for the relevant mode/workload/phase. Entry counts and waiting-thread stack totals do not supply `f`. ## Longer-term architecture

1. Establish a typed native-region IR that retains observed shapes/kinds and explicit error/deoptimization state. Hoist proven redundant checks, not required failures. Preserve IEEE/checked-integer behavior; no blanket fast-math or wrapping arithmetic.
2. Introduce shape-indexed structs and optionally homogeneous array storage behind existing Value semantics; support representation transitions and generic fallback. Evaluate total memory and cache behavior before broad migration.
3. Add escape/ownership analysis for local temporaries and known callees; borrowed views must not survive a callback or snapshot mutation without validation. Treat closures and dynamic rebinding as first-class invalidation cases.
4. Design code owners and worker artifact reuse together, with platform-specific executable memory tests. Only then consider persistent bytecode/native caches or AOT deployment as an optional mechanism.
5. Evaluate a compact VM Value/instruction format if dispatch/memory movement remains a measured bottleneck. Avoid combining representation, bytecode and language changes in one rewrite.

Static types, typed slices, bounds-check proofs, direct calls and reusable scratch buffers are adoptable strategies. Goose's compile-time-only functions, data-stack lifetimes and reference model cannot be transplanted wholesale while keeping arbitrary dynamic Kujo Values, escaping closures and snapshots. Rust-like performance may be attainable in specialized kernels; whole-language or all-suite superiority is unproven.

## If we authorize only three engineering changes next, these are the three I recommend, why, and how we will know whether each worked.

1. **A guarded native array/field-access region that amortizes validation.** QuickSort, MergeSort and NeuralNet already compile but repeatedly call generic helpers. Start with read-only, callback-free regions and retain generic fallback. Success means fewer helper/root lookups, demonstrated native loads, unchanged invalid-index/snapshot/error behavior, and repeatable whole-workload improvement without scalar/mixed-path regressions.
2. **A guarded known-callee call path with owned-argument transfer.** Sorting recursion and neural helpers repeatedly marshal through VM/native boundaries. Preserve dynamic rebinding, frame limits, errors and caller snapshots. Success means fewer marshaled Values/root operations and bridge calls, bounded live storage, native-path evidence, full three-engine parity and independently repeated target gains. Remove redundant diagnostic lookup only as a small measured component, not as the whole strategy.
3. **Cost-aware JIT admission with measured per-task reuse boundaries.** Tree functions compile near their last call; worker VMs compile the same matrix kernel repeatedly. First stop late cold compilation without harming long hot runs, then test task reuse under explicit ownership. Success means lower cold/end-to-end time and compilation counts on trees/threaded matrix, retained long-run native coverage, no stale capabilities or leaked task state, no memory regression, and all-50 correctness/regression gates passing.
