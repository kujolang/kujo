# Distance preparation and repeated-run state

The unchanged accepted CLI `b7d95533dc4f3c6007a1596352dce4a8dabd6af1250e509547da7514dde296a4`
passes **192 complete state observations** against executed pinned Rust in VM,
interpreter and JIT modes. This extends the earlier pair-score audit to generated
inputs, ordering, RNG state and checksum accumulation. No port/runtime source
changes or timing measurements are involved.

Six configurations cover `(count,size,seed,iterations)` values `(10,5,42,1)`,
`(2,500,42,1)`, `(0,1,42,3)`, `(1,1,7,3)`, `(16,32,7,3)` and `(2,4,42,3)`.
Each configuration executes both algorithms. The first Jaro configuration and
second NGram configuration match the official test inputs and final checksums
7,020 and 42. The remaining combinations are diagnostic controls, not additional
official benchmark passes.

The Rust harness embeds unchanged upstream distance and RNG-helper source at
`3c9f84ddaeec834c0631747cb789e8cfd602f993`. It constructs private benchmark states
with explicit configuration, calls their actual `prepare`, `run` and `checksum`
implementations, and records every generated string. It does not exercise the
upstream CLI/configuration loader. The selected sequence matches the inspected
harness order: prepare, one warmup, RNG reset, then each measured iteration.
All selected iteration counts imply one default warmup.

For each state, verification compares the complete ordered pair list, RNG value,
result accumulator, algorithm, case and phase. A separately implemented Ruby RNG
oracle reconstructs every generated byte and preparation-end RNG value. Kujo
also retains the prepared state and asserts that subsequent runs preserve its
zero accumulator and pair-list snapshot. Both algorithms leave RNG unchanged
during their run phases; the explicit reset is observable as state 42.

The independent verifier checks frozen identities, exact case/phase coverage,
runtime exits and raw-output hashes. Three negative controls corrupt a generated
string while retaining every accumulator value; full-state comparison rejects
them. There are 64 Rust states and 64 states per Kujo runtime, not 192 distinct
input configurations.

## Remaining scope

Both distance rows remain partial. Executed Goose comparison, operation/copy/
conversion counts, production input sizes and iterations, wider numeric/config
boundaries and native-participation evidence remain open. The per-call byte
encoding difference described in the pair audit is unchanged. The diagnostic
snapshot is a correctness assertion, not timed benchmark work. No speedup or
production-equivalence claim follows from this audit.

Reproduce with `probes/audit-distance-state.rb UPSTREAM FROZEN_KUJO NEW_OUTPUT`
and `probes/verify-distance-state.rb NEW_OUTPUT` from the repository root.
`distance-state-2026-11-03.json.gz` preserves the source/input identities,
generated harnesses, comparator/helper sources, raw states, build diagnostics,
collector and independent verification. Executables are identified by hash,
not embedded.
