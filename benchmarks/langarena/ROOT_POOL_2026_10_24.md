# Bounded native callback root reuse — 2026-10-24

Runtime commit: `09c8944`; before: `56787c7` (runtime source through `50f8357`).

Native callbacks previously discarded the vectors and handle map backing their
ownership store on every return. The VM now lends an inactive store to the next
ordinary compiled callback. Active recursion owns separate stores. After the
boundary unwinds, an owned return has already moved into `owned_return`, and all
other values and pending arguments have been released. Only empty stores are
eligible. Handle identities continue increasing across reuse, so stale handles
cannot become valid again within a recycled store.

Retention is bounded to 32 stores, each with at most 256 root slots and 256
physical frames. Oversized or unbalanced stores are dropped. The pool is not
part of restorable VM execution snapshots and retains no language values. This
change does not bypass callbacks, remove ownership checks, change array
representation, or alter the benchmark algorithm.

## Structural measurement

`probes/quicksort_allocations.rs` extracts the unchanged port QuickSort kernel.
It uses deterministic diagnostic LCG inputs, warms compilation on 1,024 elements,
and measures sorting separately from input construction. It verifies output
length, every sorted element, and saved snapshots. It counts allocation and
reallocation requests and cumulative requested bytes, not live bytes or RSS.

| 8,192-element case | Before allocations | After allocations | Before bytes | After bytes |
| --- | ---: | ---: | ---: | ---: |
| JIT unique | 190,221 | 124,380 | 48,711,508 | 28,608,056 |
| JIT snapshot | 190,223 | 124,376 | 49,825,660 | 29,720,376 |
| VM unique | 505,102 | 505,102 | 44,976,578 | 44,976,578 |
| VM snapshot | 505,104 | 505,104 | 46,090,730 | 46,090,730 |

Unique JIT allocation requests fall 34.6%; requested bytes fall 41.3%. Every
unique input retains its backing array and makes zero array-sized allocations;
every snapshot case makes one array-sized allocation and preserves the snapshot.
The snapshot trial follows the unique trial and benefits from its pool warmup,
so these two allocation totals must not be interpreted as identical cache states.
Sizes 128 and 1,024 also pass. These are debug-library structural measurements,
not release timing or official benchmark input measurements.

Reproduce after `cargo build` (substitute the actual default-feature rlib path):

```sh
rustc --edition=2021 benchmarks/langarena/probes/quicksort_allocations.rs \
  --extern kujo=target/debug/deps/libkujo-837bbf5b9bf890b9.rlib \
  -L dependency=target/debug/deps -o /tmp/kujo-quicksort-allocations
/tmp/kujo-quicksort-allocations --expect-reuse
```

## Release timing and memory

`probes/paired_root_pool.kujo` runs seven rotating rounds of before/after VM/JIT
against the unchanged test-size QuickSort workload. All 28 samples pass their
checksums. JIT's median paired speedup is **1.1567x**, with all seven pairs favoring
the candidate (range 1.1038–1.1828x). Measured-loop medians are 4.1844 seconds
before and 3.7340 seconds after; the ratio of these unpaired medians differs from
the median of paired ratios. VM's median paired ratio is 0.9849x, with a broad
0.9278–1.0962x range; this does not establish a VM improvement.

The host's reported CPU speed limit fell from 100% to 48%. No build or other
benchmark launched by this task overlapped the timing comparison, but external
work and thermal variation remain uncontrolled. These consistent local JIT
results are not a universal speed guarantee or a Goose/Rust ranking.

Four additional unchanged JIT QuickSort runs, in before/after/after/before order,
pass checksums under macOS `/usr/bin/time -l`. Maximum RSS is 50,253,824 and
51,171,328 bytes before versus 53,272,576 and 51,433,472 after. The after-sample
mean is about 3.2% higher. Peak memory footprint also increases slightly in this
small sample. Retained capacity is an intentional bounded cache cost; two
samples per variant cannot isolate that cost from allocator/OS variation. This
change establishes lower allocation traffic, **not lower peak process memory**.

Raw samples, identities, structural measurements and release checksum reports
are in [native-root-pool-2026-10-24.json](native-root-pool-2026-10-24.json).
Remaining costs include argument-vector transfer, VM-mediated native calls,
metadata/environment lookup and helper-mediated array access. No competitive
speed or production-suite completion claim follows from this allocation change.
